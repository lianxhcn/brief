# 连续编辑机制规划

日期：2026-09-15。状态：讨论稿。本文为实施方案，不是新增的正式规则；批准后归入现有 canonical docs。本轮不改程序、定时器或已发布内容。

## 1. 当前基础与缺口

已有双端共享数据、14 天去重、逐刊检查、论文构成校验、逐日运行状态和当期部署核验。9 月 15 日确实复用了 14 日期刊记录，并非全量重搜。

本轮核对发现：

- config/source-registry.yml 已有会议清单，但部分入口为单届通知；daily_sources 中 Python 仅列 PyPI 首页，缺少对应 R 入口。登记网址不能代表有效覆盖。
- config/paper-policy.json 有29刊范围和4/7天检查有效期，但没有充分表达编辑优先次序。
- ops-local/state 和 candidates 的目录清单仅见早期记录；近期证据主要分散在 runs，缺少可直接接续的统一视图。
- logs/prepare_20260914.py 和 prepare_20260915.py 按日组织候选并修改脚本组稿，不宜作为长期生产入口。
- scripts/build_local_draft.py 已有台账组装函数，但 CLI 仍以旧 A-02 frozen 报错退出，与现行日常授权不一致。须迁移到现行审核链，不能只删除闸门。
- docs/tasks/README.md 仍有醒目的旧冻结状态，应增加当前状态导引，保留历史证据。

15 日暴露的问题是软件生态覆盖不足、会议重复后过早停止发现，以及以宽口径顶刊比例代替真实候选比较。构建、测试和部署成功不等于编辑质量合格。

## 2. 连续记录的职责

| 记录 | 既有位置的扩展 | 内容与约束 |
| --- | --- | --- |
| 来源清单 | config/source-registry.yml | 稳定 source_id、类别/生态、官方入口、入口类型、覆盖范围、频率、替代入口；只登记可核实能力 |
| 来源进度 | ops-local/state，关联 runs 中检查事件 | 最后尝试、最后成功、覆盖区间、分页位置/期次、下次检查、证据与失败原因 |
| 持续候选池 | ops-local/candidates | 成果 ID、首次公开/更新/发现日期、版本关联、核验程度、读者价值、待补证及采用/暂缓/排除原因 |
| 发布台账 | 从正式期次、releases、publication.json 重建 | 成果、日期、渠道、版本、提交、部署与交付证据 |

每日 runs 保存原始检查事件和当期快照，state 是可重建的当前视图。当前视图和历史日志不能各自成为独立事实真源。

检查状态保留 found/no-eligible/access-failed/not-searched，另记发现、初筛、核验、采用数量。没有新消息、重复、访问失败和没有合格内容分别说明。只有成功完成实际覆盖后才能推进检查终点；分页截断和部分失败不能标记整段完成。复用原检查日期，不能改成今天。

候选状态建议为：待初筛、待核验、合格待选、当期已选、已发布、暂缓、排除、过期。昨日合格但未选的内容继续比较，缺证候选只补缺项，明确排除的不要每天重做。超过时效窗口不再当作新消息；有价值遗漏按既有例外办理。

论文跨平台版本、软件原始项目与生态、会议届次必须关联去重。网站发布、TXT 生成、共享交付和实际微信发送分别记录；无送达证据不能推断已发送。旧短稿不因网页修订静默覆盖。

## 3. 来源入口和频率建议

以下为待讨论默认值，不直接替换现行规则。

| 来源 | 工作安排 |
| --- | --- |
| 连享会推文 | 每日增量检查，保留真实覆盖终点；历史 C-08 未知不补造 |
| 期刊正式目录 | 新期次出现时核对，已覆盖期次不每日全文重扫；定期检查更正和漏项 |
| 期刊在线优先发表页 | 与正式目录分开，每周两轮，最长间隔符合现行4天有效期；留重叠窗口应对延迟索引 |
| 定向 arXiv | 工作日检查新增，保留首次公开和版本日期 |
| NBER | 新周批次检查，采用时核验；不把旧文修订当首发 |
| CEPR/IZA/IMF/World Bank | 按周错峰，遵守现行7天有效期 |
| Stata/R/Python | 三生态均进入轮查，每周至少两轮作为试运行目标；兼顾熟悉项目更新与新项目发现，不遍历整个CRAN/PyPI |
| 会议 | 长期高校/学会栏目每周两轮，候选不足补查；每天检查候选截止日，采用前核验变更 |

会议的长期发现栏目与单届核验通知分开。PyPI/CRAN 首页不是完成检查的证据，应落实到更新列表或定向项目发布入口。新入口先试读，记录覆盖限制，再登记为稳定来源。ETag、Last-Modified、列表指纹仅在实际支持时采用。

来源身份与编辑优先级分开。AER、QJE、JFE、JF、RFS 是用户强调的优先来源，不能解释为排他五刊名单；既有 JPE、Econometrica、REStud 等重要来源继续保留。具体分组待裁定，不因本轮讨论自动删除 Social Forces 等跨学科来源。arXiv 仍按前沿价值参与延伸阅读，不因纠正过去集中问题而受到惩罚性排除。

## 4. 每日顺序与编辑验收

1. 检查当期完成证据与实际活动状态，恢复中断阶段，防止并发。
2. 读取来源进度、候选池、发布台账，生成到期检查、增量发现、待补证和临近截止任务。
3. 合并新增并按成果去重，再核验拟采用内容。不得先填满正文再倒写检索理由。
4. 比较重要期刊、方法论文、软件、会议和工作论文；候选不足时先补查已登记入口，再采用论文补位。
5. 分别出具来源覆盖结论与选稿结论，通过后使用既有 renderer、validator、构建及发布流程。
6. 部署与当期首页、正文、搜索核验完成后更新台账，恢复次日07:15；共享TXT单独核验。

新增验收重点：

- 到期来源有实际结果或有效复用依据，失败不能冒充无合格内容。
- R/Python 缺少有效记录时，不能概括为软件不足；先补查或明确保留覆盖缺口。
- 少数会议重复后要检查长期发现入口的覆盖，不能立即结束整类检索。
- 重点论文记录真实优先候选比较，不只数 top 标记。高优先候选未选要有简短理由。
- 全论文期次或高度集中结果触发额外编辑复核，可以有据通过，不硬设软件/会议入选名额。
- 保留数量、日期、引文、标签、去重和部署验收。控制低价值追查成本，不将耗时达到预算当作发布资格。

## 5. 实施顺序

### 阶段一：整理和迁移

核验来源入口，区分长期栏目与单届通知。汇总近期 runs、正式期次和发布证据，重建来源进度、候选和渠道台账。缺失保持 unknown，不删除原日志、不关闭 C-08 历史债务。

交付可读来源备忘录、候选池快照、覆盖缺口、旧新记录对应关系。首次投入以建立可复用基础为目的。

### 阶段二：统一日常入口

复用既有组稿函数、paper_policy、两端renderer和发布检查，增加任务清单、来源结果导入、状态迁移与恢复控制。停止新增按日期专用 prepare 脚本，旧脚本作为历史证据保存。自动抓取与人工辅助核验写同一种记录，不承诺全网无人采集。

### 阶段三：隔离验证后接入生产

先回放14—15日证据，验证复用原日期、识别已发成果及暴露R/Python缺口；不能把回放当成重新联网完成覆盖。再进行连续两轮真实增量试运行，通过后才更新现有定时任务入口。

验收场景：重复运行不增加重复候选；期次未变但在线新增能够发现；断网/分页不全不推进覆盖；昨日未选候选保留、过期不伪装新文；跨平台版本和会议延期正确关联；推送后中断接续部署而非重发；缺口阻止虚假无合格结论；保护 Task12 等无关工作和旧短稿。

现有每日07:15、未完成补查、成功后次日再启的时间规则不因规划而改变。试运行期不静默切换生产，也不在新机制未验证时宣称已完成。
