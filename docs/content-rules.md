# 内容长期规则

canonical owner：来源、筛选、去重、引文和微信格式。生效日期：2026-09-05。

## 1. 来源与核验

- C-01 [HARD]：宁缺毋滥，不编造作者、论文、DOI、版本、日期、费用、链接或结果。最终依据使用官方、作者或维护方可核验资料；搜索、聚合、转载仅用于发现。
- C-02 [HARD]：执行 14 天内容去重，同一论文跨版本 / 来源不重复充数。保留来源 URL、核验日期 (`retrieved_date` 或明确映射的 `verification_date`)、入选理由和去重证据。
- C-03 [DEFAULT]：当前论文按 DOI / 正式 URL / 标题、工具按包名 / 项目 URL、会议按主办方 / 标题 / 年份 / 截止日核对。软件版本去重最终 key 为 [PENDING]，不得自行将“包名 + 版本”定为硬规则。
- C-04 [PENDING]：完整最终来源白名单尚未确认。现有注册表和代码名单是当前入口 / 实现，不等于最终名单。[DEFAULT] 检索覆盖 AER、QJE、JPE、Econometrica、REStud，扩展领域期刊先说明并编辑复核；软件优先近 30 天、论文近 90 天，较早材料说明实际日期，不冒充当天首发。
- C-05 [HARD]：区分正式发表、forthcoming、working paper。forthcoming 要有期刊或作者录用证据，R&R 不算；核验 PDF 版本及公开可访问性。程序字段检查、AI 摘要不能替代人工事实和学术判断；未实测不得声称软件或计量结果正确。
- C-06 [DEFAULT]：工作论文优先 arXiv，NBER 补充，CEPR / SSRN 选有明确研究、方法或代码价值的材料。工具以 SSC / Stata Journal、CRAN / PyPI、正式 release 或有安装文档的作者维护仓库为依据。记录生态、名称、版本、发布日期、来源及用途，不把文档版本当发行版。
- C-07 [HARD]：会议 / 征文使用官方通知，核验主办方、主题、截止日与费用。暑校、训练营、工作坊须明确免费或公益；收费商业培训和费用不明活动不进入成品。[DEFAULT] 优先至少 7 天投稿窗口；中文期刊入口用于征文、专题、专栏、工作坊监测，《中国社会科学》《社会学研究》经主题匹配复核，区分《计量经济学报》与《计量学报》。

## 2. 新推文与构成

- C-08 [HARD]：每日检查 `lianxh.cn` 自上一期覆盖时点之后发布、尚未进入微信短版的新推文。存在则必须收录，默认最高优先级、原则上第 1 条，一般 1 篇、必要时 2 篇；直接链接对应文章，不因其他候选已满删除新推文。无更新不造占位条目。
- C-09 [HARD]：日常短版常规 4–5 条，信息不足允许 3 条，不凑数降质。保留已确认日常构成：1–2 篇顶刊正式发表 / forthcoming 论文、1–2 条 Stata / R / Python 发布或更新，会议可选，不能挤掉 C-08；无法满足时记录缺口，不强行发布。网页 extended 最多 5 条、日常总数最多 10 条，均非凑数目标。明确制作独立会议增刊时沿用 2–3 条合格会议；日常会议不受该门槛限制。历史构成依据见审计；最终来源名单仍按 C-04 待定。

## 3. 微信短版

- C-10 [HARD]：一份纯文本 `YYYY-MM-DD.txt`；整期标题精确为 `📙 连享会 · 快讯 | YYYY.MM.DD`。单条标题为 `Emoji 01｜类型 · 来源：标题`。
- C-11 [HARD]：只使用下表 Emoji，仅作分类识别；引文、主页、PDF、版本等字段不额外加图标，不自行引入人物、手势、肤色、国旗、宗教、政治等图标。

| Emoji | 用途 |
|---|---|
| 📙 | 整期快讯 |
| ✍️ | 新推文 |
| 📰 | 论文 |
| 📦 | 软件 / 命令 / 数据工具 |
| 📅 | 会议 / 征文 |
| 🌐 | 更多内容 |

- C-12 [HARD]：标题下直接写 1–2 句介绍，不写“提要：”“摘要：”“简介：”。按类型重新撰写，不机械截取 page_note 或 abstract：推文讲解决的问题和点击价值；论文讲做了什么和关注理由；软件讲用途与情境；会议讲人群、截止日与通知入口。
- C-13 [HARD]：论文短引文保留主标题，副标题可省略；无需完整 myAPA，也不强制 DOI。[DEFAULT] 使用 `引文：Author(s) (Year). Main title. Journal abbreviation / source.`，作者多时可用 `et al.`。
- C-14 [HARD]：新推文 1 个 URL；论文原则上最多 2 个主要 URL；软件 / 命令原则上 1 个最权威入口；会议 / 征文原则上 1 个官方通知入口。
- C-15 [HARD]：每个纯文本 URL 左右各恰好 1 个半角空格；中文冒号与 URL 间 1 个空格，URL 后保留 1 个空格且不得紧接中文句号、逗号、括号等标点。formatter 与 validator 均须显式检查，不依赖 Markdown 自动链接。示意 `主页：␠https://example.com/article␠` 中 ␠ 表示 U+0020，最终文本必须使用真实空格。
- C-16 [HARD]：禁止 Markdown link，如 `[PDF](...)`。每条内部不空行，条目之间恰空 1 行，不出现连续两个以上空行。
- C-17 [HARD]：条目间无分割线；全文只在正文结束后出现一次 `——`，之后固定 `🌐 更多内容：` 加本期正式 issue URL，空格遵守 C-15。
- C-18 [HARD]：尾部不使用“本期详版”“今日详情”“完整内容”“查看详情”“网页版”，不追加官网首页、课程或 GitHub CTA；课程推广不进微信正文。

## 4. 网站论文 myAPA

C-19 [HARD]：网站论文引文使用项目 myAPA，不能沿用微信短引文。基本顺序：

```text
Author(s). (Year). Title. Journal or source, volume(issue), pages. [Link](...), [PDF](...), [Google](...)
```

保留作者原始顺序，最后一位前用 `&`；题名 sentence case，完整保留主副标题。核实期刊 / 来源、卷期页码，不编造缺失元数据。

C-20 [HARD]：DOI 可用时 Link 优先 `https://doi.org/...`。PDF 仅列官方、作者主页或其他可靠公开可访问版本，受限 / 不可访问不强列。Google 使用正确编码的 Scholar 检索 URL，无未编码空格或特殊字符。缺少可靠链接直接省略，不填占位，不以 DOI 冒充 PDF。

本项目明确规则与全局 myAPA 默认的 DOI 兜底、空链接占位或强制保留 Google 字段不同，网站详版遵守上述项目规则。旧规范的废弃登记见 [project-rules](project-rules.md)；实现差异见 [债务](tasks/implementation-debt.md)。
