# 内容长期规则

canonical owner：来源、筛选、去重、引文和微信格式。生效日期：2026-09-05；来源与筛选更新日期：2026-09-07，依据 D-20260907-03。

## 1. 来源与核验

- C-01 [HARD]：宁缺毋滥，不编造作者、论文、DOI、版本、日期、费用、链接或结果。最终依据使用官方、作者或维护方可核验资料；搜索、聚合、转载仅用于发现。读者主题与价值、核验成本取舍见第 1.1 节。
- C-02 [HARD]：执行 14 天近期重复控制，并保留长期成果对应关系；第 15 天不自动变成新闻。普通实质更新受近期控制，重要勘误、撤回、影响结果的软件修复、会议延期或取消允许例外，核验后优先审核，不构成发布授权。保留来源 URL、核验日期 (`retrieved_date` 或明确映射的 `verification_date`)、入选理由与去重证据。详见第 1.6 节。
- C-03 [HARD]：按同一研究、同届会议和原始软件项目识别成果，会议延期不产生新会议，同名跨生态软件不直接合并；无法判断时暂缓。[DEFAULT] 使用 DOI、预印本编号、作者、题名、内容及原始项目交叉核对，详见第 1.6 节。[PENDING] 软件最终去重 key 尚需结合数据结构验证，不将“包名 + 版本”擅定为完整规则。
- C-04 [HARD]：来源范围与筛选政策已确认，以 1808 期刊母表及专项补充为依据，完整分组和两端优先见第 1.2 节。母表不是每日遍历清单。[DEFAULT] 论文和软件优先最近 14 天，特别有价值的遗漏最多放宽至 30 天，保留真实日期，详见第 1.6 节。[PENDING] 具体抓取入口、注册表覆盖和采集稳定性仍待验证。
- C-05 [HARD]：区分正式发表、forthcoming、working paper；forthcoming 要有期刊或作者录用证据，R&R 不算。权威原始摘要可支持简讯，具体数字、因果解释和方法优劣需正文依据；记录实际依据与版本。核验 PDF 版本和公开可访问性，缺失可靠链接按 C-20 省略。程序字段检查、AI 摘要不能替代人工事实与学术判断；未实测不得声称软件或计量结果正确。全文有限追查与复现材料分层见第 1.4 节。
- C-06 [HARD]：软件与工作论文按第 1.3、1.4 节的来源分工与门槛筛选。GitHub-only 项目有清楚安装说明和示例可入选；不设 stars、下载量、引用量或软件论文硬门槛，不要求日常逐包实测或完整复现，不遍历整个 CRAN / PyPI。
- C-07 [HARD]：会议 / 征文依官方信息核验，国内重点、费用与有效日期口径见第 1.5 节。正常学术会议注册费不构成排除理由；商业培训和收费暑校不纳入，workshop 按实际性质判断，未知费用不得写为免费。按有效截止日筛选，不限原公告近 14 天；首次介绍后最多一次临近截止提醒，延期 / 取消按 C-02 处理。[DEFAULT] 优先至少 7 天投稿窗口。中文期刊也可作为论文来源。

### 1.1 C-01：读者与筛选原则

快讯服务学术研究，也覆盖硕士毕业后从事数据分析、行业研究和报告写作的人群。主题范围包括：

- 计量方法与因果推断：估计、检验、诊断、异质性与敏感性分析。
- 数据处理与研究工具：Stata / R / Python、文本分析、可视化和结果输出。
- 经济、金融、会计、管理等领域中有研究启发的应用论文。
- AI 辅助学术研究：文献、数据、编程、复现与事实核验。
- 就业导向的数据分析、应用机器学习、行业分析、研究报告及写作实践。

就业内容应能帮助读者完成具体工作，例如构造业务指标、诊断指标变化、评估预测模型、比较行业、组织报告证据或改善图表表达。公开行业研究报告本身可以入选，不要求全部转化为软件教程。

一般产品宣传、与研究或分析工作关系较弱的 AI 新闻、缺少依据的热点评论不作为常规重点。来源范围较宽不代表必须逐日覆盖全部领域，也不设每期学科、软件语言或就业内容的固定配额。就业导向拓展不改变 U-06、C-18 中课程推广由网站承担、不进入微信正文的规则。

**价值与成本共同约束筛选。** 先从稳定入口发现候选，再核验少量拟采用条目的事实。普通条目不反复寻找全文、修复采集入口或搭建运行环境；高价值且确需裁定的疑点才集中交给用户。宁缺毋滥，不能为满足数量而降低证据要求。

### 1.2 C-04：期刊母表与两端选择

#### 1.2.1 母表依据

此前另拟的 32 种期刊两档清单只保留为讨论历史，不再作为独立名单。母表按学科区分顶尖或核心期刊与领域强刊，本项目沿用这一阅读范围，不自行建立跨学科统一排名。

- 微信短版：在相关性和证据合格的前提下，优先母表中各领域最顶尖期刊的最新论文。

- 延伸阅读优先利用本轮已经核验的候选；没有合格内容时不凑满 5 条。

#### 1.2.5 名称与入口核验

期刊全名是核对依据，不能单凭缩写识别。尤其 `JAE` 可能指 Journal of Applied Econometrics，也可能指 Journal of Accounting and Economics，二者必须分别记录。也要区分《计量经济学报》与《计量学报》。

母表中的链接是待核对的来源线索，不能直接视为已经验证的采集入口。本轮完成了内容分组，未逐一验证所有期刊主页、RSS、API 或自动采集稳定性。选择期刊范围与验证技术入口分别记录。

### 1.3 C-06：软件来源与质量门槛

Stata 优先官方信息、Stata Journal、SSC 和作者正式维护的项目。R 优先 CRAN 与原始文档，Python 优先 PyPI 与原始项目文档；GitHub-only 项目有清楚安装说明和示例也可入选。

论坛、公众号和他人推荐可以发现线索，最终回到官方、作者或维护方资料核验。CRAN、PyPI 等作为收录和版本核验入口，不意味着遍历全站所有新包。新项目主要通过主题检索、软件论文和作者线索发现；成熟项目可形成小型跟踪清单，具体技术清单不在本轮冒充已经实现。

拟入选软件至少核对：

- 作者或维护方、软件生态、名称与原始项目是否对应。
- 用途、适用情境、安装说明、文档和最小示例。
- 发行版本、实际发布日期、更新内容，避免把文档构建版本当作发行版本。
- 对拟推荐用途有实质影响的已知问题；涉及估计与推断时核对方法依据和限制。

不设置 stars、下载量、引用量或已发表软件论文的硬门槛。成熟软件短期没有更新，不自动判为不可用。日常不要求逐包安装、跑完整测试或验证全部计量结果；未实测不得写成已实测、可直接跑通或结果正确。

### 1.4 C-05、C-06：工作论文、全文与复现材料

#### 1.4.1 工作论文来源

- NBER 按研究主题常规筛选。
- arXiv 只跟踪计量、因果推断、相关统计学习及 AI 辅助研究等方向，不做全站泛筛。
- CEPR、IZA、IMF、World Bank 的指定工作论文系列纳入常规监测，但不要求每天重复检查。
- SSRN、大学工作论文和作者主页先通过人工线索补充，不做全站搜索。

工作论文明确标注状态，不以机构名气代替内容判断。正式发表、forthcoming 与 working paper 分开；forthcoming 仍需期刊或作者的录用证据，R&R 不算。

#### 1.4.2 依据范围与全文查找

允许依据权威原始摘要作简短事实介绍。具体数字、因果解释和方法优劣仍需核对相关正文；不把 AI 生成的摘要或转载摘要当作原始依据。记录实际采用的是摘要还是正文，不声称完成了未做的全文审读。

开放全文优先，完整 HTML 正文与 PDF 均可用。[DEFAULT] 寻找全文限正式入口及少量可靠公开替代来源，通常正式入口加一个有希望的替代来源即停止；有明确可信的直达线索时可作有限补查。这是可调整的技术默认值，不是要求每条穷尽搜索。

正式版受限、使用公开工作论文版本时，摘要和结果必须与实际阅读版本对应。版本对应不上、证据不足或存在明显矛盾的条目暂不进入当期。一次工具失败只表示本次未能核验，不能直接写成没有公开全文。

PDF 仅展示经过版本与公开可访问性核验的链接。没有可靠 PDF 时省略，继续遵守 C-20 和已验收的链接数量及格式规则。

#### 1.4.3 复现材料

代码和数据是加分项，不是所有论文的硬性条件。日常只核对入口、基本说明和与论文的对应关系，不把完整复现作为快讯任务。

如实区分：公开代码和数据；公开代码但数据受限；部分示例或模拟程序；尚未找到公开材料。有 GitHub 链接不等于完整复现包，材料齐全也不等于已经成功复现。商业数据库或受限数据不自动导致论文被排除。

### 1.5 C-07：国内优先的会议与征文

重点跟踪中国经济学年会、中国金融学年会、YES 年会、香樟经济学年会，以及核心期刊征文、可信学会或高校主办的相关专题会议。年会与同品牌各地专题 Seminar 分别判断，小型讲座和地方活动不自动纳入常规监测。

会议只分本项目的编辑优先级，不建立复杂评分，不宣称通用学术等级。微信群国内优先；国际会议在高度相关、国内举办或方便线上参与时补充。网站扩展范围可以更宽，仍需满足主题与证据要求。

日期与入口以主办方、承办高校、会议秘书处或可确认身份的官方账号为依据。聚合站用于发现线索。核对当届年份、主办方、主题、举办时间与地点、投稿或报名入口、相关截止日期及已公布费用，检查后续延期或变更公告。未知费用不得写为免费。

正规学术会议注册费不构成排除理由；商业培训和收费暑校不纳入。公益或明确免费活动可按价值选择。对 workshop / 工作坊按实际性质判断：采用论文报告、学术评议形式的学术会议适用会议口径；商业教学培训适用培训排除口径，不能只凭名称判断。费用或活动性质的疑点影响读者决策且无法澄清时暂缓。

会议按投稿、报名是否有效筛选，不要求原公告必须在最近 14 天发布。投稿截止、报名截止和会议日期分别记录。首次有效介绍后至多再作一次临近截止提醒，并控制近期重复；延期、取消等实质变更按第 1.6 节处理。

[DEFAULT] 既有至少保留 7 天投稿窗口的要求继续作为 DEFAULT，不是禁止首次发现临近截止的高价值活动；是否提示由有效性和读者可行动性判断。

### 1.6 C-02、C-03、C-04：去重、版本与时效

#### 1.6.1 去重对象

14 天是近期重复推送控制窗口，不是第 15 天重新变成新闻的许可。保留长期已发布成果的对应关系，同一内容跨平台、改标题或换 URL 不重复充数。

- 论文结合 DOI、预印本编号、作者、题名和内容识别同一研究；期刊版与工作论文版建立对应关系。
- 会议按同一届活动识别，延期改变截止日不应自动变成另一个会议。
- 软件核对生态、原始项目和具体更新；同名跨生态软件不直接合并，同一项目多平台发布不重复计数。
- 同一研究的论文与配套软件按信息增量判断，同一期通常合并；不同论文主题相近不直接视为重复。

无法判断是否同一成果时暂缓采用并保留证据。软件最终去重 key 尚需结合现有数据结构验证；本轮确定的是去重语义，不把“包名 + 版本”擅自升级为完整业务规则。

#### 1.6.2 值得再次介绍的变化

新增重要方法、数据、结论、软件功能或公开复现材料，可以作为更新候选，并说明相对前次介绍的新增内容。改标题、补卷期页码、普通文字修订、无实质变化的版本升级通常只更新记录。

普通实质更新仍受近期重复控制，不因版本号增加而自动突破 14 天窗口。重要勘误、撤回、影响结果的软件修复，以及会议延期或取消，允许突破一般去重限制，核验后优先进入审核。版本号大小不是唯一依据，小补丁也可能修复重要错误。此例外是内容去重例外，不构成自动发布授权。

#### 1.6.3 时效窗口

- [DEFAULT] 论文和软件优先最近 14 天；特别有价值的遗漏可放宽至 30 天，保留真实日期。
- 分开记录首次公开日期、当前版本或实质更新日期、本项目首次发现日期，不能用发现日期伪装首发。
- 新行业报告与实践案例按快讯价值择优；长期教程和旧材料作为核验、配套或后续选题资源，不因今天首次发现而包装为新消息。
- 会议依有效截止日期筛选；更正和状态变更核验后及时处理。

## 3. 微信短版

- C-10 [HARD]：一份纯文本 `YYYY-MM-DD.txt`；整期标题精确为 `📙 连享会 · 快讯 | YYYY.MM.DD`。单条标题为 `Emoji NN｜类型[ · 来源]：标题`，NN 为连续两位序号。来源为条件字段，仅在有助于快速识别且已有可靠结构化字段时显示；不得从自然语言标题、URL 或其他非结构化信息猜测。默认类型为新推文、论文、软件、命令、资源、会议征稿；论文可显示可靠期刊来源，软件 / 命令可显示可靠平台。新推文采用 `✍️ NN｜新推文：标题`，不重复显示连享会或 lianxh.cn。标题已含同一可靠来源的精确前缀 (如 `QJE：`、`R：`) 时，只去掉该重复前缀再组合，不作语义猜测。
- C-11 [HARD]：只使用下表 Emoji，仅作分类识别；引文、主页、PDF、版本等字段不额外加图标，不自行引入人物、手势、肤色、国旗、宗教、政治等图标。

| Emoji | 用途 |
|---|---|
| 📙 | 整期快讯 |
| ✍️ | 新推文 |
| 📰 | 论文 |
| 📦 | 软件 / 命令 / 数据工具 |
| 📅 | 会议 / 征文 |
| 🌐 | 更多内容 |

- C-12 [HARD]：标题下直接写 1–2 句介绍，不写“提要：”“摘要：”“简介：”。按类型重新撰写，不机械截取 page_note 或 abstract：推文讲解决的问题和点击价值；论文讲做了什么和关注理由；软件讲用途与情境；会议讲人群、截止日与通知入口。
- C-13 [HARD]：论文短引文保留主标题，副标题可省略；无需完整 myAPA，也不强制 DOI。[DEFAULT] 使用 `引文：Author(s) (Year). Main title. Journal abbreviation / source.`，作者多时可用 `et al.`。
- C-14 [HARD]：新推文 1 个 URL；论文原则上最多 2 个主要 URL；软件 / 命令原则上 1 个最权威入口；会议 / 征文原则上 1 个官方通知入口。
- C-15 [HARD]：每个纯文本 URL 左右各恰好 1 个半角空格；中文冒号与 URL 间 1 个空格，URL 后保留 1 个空格且不得紧接中文句号、逗号、括号等标点。formatter 与 validator 均须显式检查，不依赖 Markdown 自动链接。示意 `主页：␠https://example.com/article␠` 中 ␠ 表示 U+0020，最终文本必须使用真实空格。
- C-16 [HARD]：禁止 Markdown link，如 `[PDF](...)`。每条内部不空行，条目之间恰空 1 行，不出现连续两个以上空行。
- C-17 [HARD]：条目间无分割线；全文只在正文结束后出现一次 `——`，之后固定 `🌐 更多内容：` 加本期正式 issue URL，空格遵守 C-15。
- C-18 [HARD]：尾部不使用“本期详版”“今日详情”“完整内容”“查看详情”“网页版”，不追加官网首页、课程或 GitHub CTA；课程推广不进微信正文。

## 4. 网站论文 myAPA

C-19 [HARD]：网站论文引文使用项目 myAPA，不能沿用微信短引文。基本顺序：

```text
Author(s). (Year). Title. Journal or source, volume(issue), pages. [Link](...), [PDF](...), [Google](...)
```

保留作者原始顺序，最后一位前用 `&`；题名 sentence case，完整保留主副标题。核实期刊 / 来源、卷期页码，不编造缺失元数据。

C-20 [HARD]：DOI 可用时 Link 优先 `https://doi.org/...`。PDF 仅列官方、作者主页或其他可靠公开可访问版本，受限 / 不可访问不强列。Google 使用正确编码的 Scholar 检索 URL，无未编码空格或特殊字符。缺少可靠链接直接省略，不填占位，不以 DOI 冒充 PDF。

本项目明确规则与全局 myAPA 默认的 DOI 兜底、空链接占位或强制保留 Google 字段不同，网站详版遵守上述项目规则。旧规范的废弃登记见 [project-rules](project-rules.md)；实现差异见 [债务](tasks/implementation-debt.md)。
